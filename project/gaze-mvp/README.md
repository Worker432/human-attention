# Vision Gaze MVP для macOS

## Сбор датасета на рекламных изображениях

Откройте **`Начать сбор.command`** двойным щелчком. Запускается `collect_app.py` в существующем `.venv`. Beam должен быть включён и откалиброван на выбранном экране. По умолчанию используется основной экран macOS.

На начальном экране проверьте зелёную точку относительно центрального креста и нажмите **Space**, когда готовы. При отсутствии свежего сигнала MEDIUM/HIGH сбор не начинается. Во время просмотра изображений маркер взгляда и подписи скрыты.

**Просмотр записей:** на начальном экране или паузе нажмите кнопку **«Просмотреть записи (R)»**. Панель показывает сохранённые изображения, статус и длительность просмотра, число точек и долю уверенных точек. Выберите изображение слева, нажмите **«Воспроизвести»** или двигайте ползунок времени. Треугольник обозначает начало, квадрат — текущую/последнюю точку. Паузы сигнала разрывают линию. При желании сохраните текущий вид кнопкой **«Сохранить картинку с траекторией…»**.

Клавиша **R** во время сбора сначала прерывает текущий просмотр и ставит сбор на паузу, затем открывает панель. После закрытия панели нажмите Space, чтобы продолжить. Можно также открыть **`Просмотреть записи.command`** отдельно — без Beam и без запуска нового сбора. Просмотр читает базу, не изменяя записи и прогресс. Кнопка **«Обновить список»** подхватывает новые записи. При изменении/удалении исходного изображения наложение скрывается с пояснением.

- Каждое изображение показывается **5 секунд**, затем **1 секунду** — центральный крест. Свободно рассматривайте картинки, специальной задачи поиска нет.
- Используются все **64 454** JPG из `dataset/PittImageVideoAdsDataset/pitt_ads_images`. Список перемешивается один раз с seed=42 и сохраняется. Добавленные позднее файлы не включаются в уже начатый сбор.
- **Space** — пауза / продолжение. **→** — пропустить изображение. **Esc/Q** — сохранить и выйти. После каждых 50 полных просмотров приложение предлагает перерыв.
- Просмотренные изображения больше не показываются, включая прерванные при паузе, выходе, потере сигнала, скрытии окна и аварийном завершении. Такие записи имеют отдельный статус и не должны считаться полными пятисекундными просмотрами. Изображение, подготовленное во время креста, но ещё не показанное, остаётся в очереди.
- Потеря сигнала более чем на 0.5 секунды прерывает текущий просмотр и ставит сбор на паузу. Более короткие пропуски сохраняются в записи; используйте количество валидных точек для контроля качества. Изменение геометрии экрана требует перезапуска.

Прогресс и данные сохраняются в **`collected/p001/dataset.sqlite3`** после каждого пакета точек. Резервная копия во время работы должна включать WAL-файлы; проще экспортировать согласованный снимок через **`Экспорт CSV.command`** или закрыть приложение перед копированием базы. Одна папка сбора защищена от одновременного запуска двух экземпляров. Не удаляйте её, чтобы сохранялся прогресс.

Экспорт создаёт новую папку `collected/export-<дата-время>` с пятью CSV:

| Файл | Содержание |
| --- | --- |
| `metadata.csv` | Участник p001, фиксированный протокол, длительность, исходная папка и seed |
| `images.csv` | Постоянный ID и относительный путь каждого изображения в очереди |
| `runs.csv` | Запуски, выбранный экран, система координат и параметры источника |
| `trials.csv` | ID изображения и запуска, SHA-256 показанного файла, время начала и длительность показа, статус, размер исходного изображения и прямоугольник показа, число всех/валидных/попавших в изображение точек |
| `samples.csv` | ID просмотра, номер обновления, время компьютера, монотонное время, timestamp Beam, время от начала показа, confidence, valid, inside_image, исходные нормализованные координаты Beam, координаты экрана и исходного изображения |

Связи: `samples.trial_id → trials.id`, `trials.image_id → images.id`, `trials.run_id → runs.id`. Параметры протокола и геометрия хранятся как JSON в соответствующих колонках. Для анализа выбирайте `trials.status='completed'`, `samples.valid=1`, `samples.inside_image=1`, дополнительно проверяя полноту записи. Статус completed означает полную длительность показа, а не доказанную точность взгляда.

Координаты экрана — локальные логические пиксели Qt, координаты изображения — пиксели исходного файла, начало слева сверху. Изображение вписывается целиком с сохранением пропорций. Сглаживание и обрезка координат не применяются: точки на полях и за границами сохраняются с отметкой `inside_image=0`. LOW/LOST_TRACKING и отсутствующие координаты не считаются валидными. Сохраняются обновления, полученные SDK; это не гарантия сохранения каждого кадра камеры. SDK-время и время чтения компьютером сохранены отдельно; задержка трекера не компенсируется. Начало показа отмечается при первой отрисовке Qt, без аппаратного измерения момента появления пикселей.

Это исходные точки взгляда для одного участника. Фиксации, длительности фиксаций и саккады ещё не выделяются: для них нужен отдельный этап обработки с выбранными и проверенными порогами. Исходные изображения остаются в папке dataset; экспорт не копирует их. SHA-256 позволяет проверить соответствие показанных файлов.

Запуск с другого экрана (список: `python beam_app.py --list-screens`):

```bash
.venv/bin/python collect_app.py --screen 1
```

Другой протокол (например, другая длительность) требует отдельной папки `--output`, чтобы не смешивать условия:

```bash
.venv/bin/python collect_app.py --duration 3 --output collected/p001-3sec
```

Проверка интерфейса без Beam: `python collect_app.py --ui-only`. Этот режим использует отдельную папку `collected/ui-preview` и не начинает показ без трекинга. Автоматические тесты используют временные папки и синтетические точки, не изменяя рабочий прогресс.

Фиксированные 5 секунд выбраны как первый протокол свободного просмотра (такой срок используется в CAT2000; в OSIE — 3 секунды): [MIT Saliency Benchmark, datasets](https://saliency.mit.edu/datasets.html). Это не универсально оптимальная длительность. Самостоятельное переключение по кнопке сделало бы длительность зависимой от участника; здесь кнопка пропуска помечает просмотр как неполный. Полный набор с интервалами — около 107 часов без учёта перерывов.

## Рекомендуемый режим: Beam Eye Tracker

Если Beam Eye Tracker уже установлен и откалиброван, используйте `beam_app.py`. В этом режиме Apple Vision и собственная 39-точечная калибровка не используются: программа получает от Beam готовую точку взгляда и confidence, дополнительно сглаживает её, показывает маркер и сохраняет CSV.

Beam Eye Tracker должен быть версии 2.6.3 или новее. Для macOS с Retina и несколькими экранами рекомендуется 2.6.5 или новее. Установите Python SDK в существующее окружение:

```bash
cd "/Users/zaxharmerkurev/Documents/dimplom/project/gaze-mvp"
source .venv/bin/activate
python -m pip install -r requirements-beam.txt
```

Сначала узнайте номера подключённых экранов:

```bash
python beam_app.py --list-screens
```

Проверьте подключение в обычном окне, подставив номер нужного монитора или телевизора:

```bash
python -u beam_app.py --screen 0 --windowed
```

Если зелёная точка движется правильно, запустите прозрачный оверлей поверх браузера:

```bash
python -u beam_app.py --screen 0 --overlay
```

Оверлей пропускает клики в расположенные под ним приложения. Завершайте его через `Ctrl+C` в Terminal. Красный индикатор `REC gaze` показывает, что ведётся запись. Результаты создаются в `sessions/beam-<дата-время>/`: `trajectory.csv` содержит `timestamp,x,y,confidence`, а `session.json` — выбранный экран и параметры. Координаты локальны для выбранного экрана, начало находится в его левом верхнем углу.

По умолчанию кадры с confidence `LOW` и `LOST_TRACKING` не записываются. Для диагностического режима можно разрешить `LOW`:

```bash
python beam_app.py --screen 0 --windowed --min-confidence low --smoothing 0.12
```

Beam должен быть запущен, переключатель **Tracker** должен находиться в положении **On**, а калибровка должна быть выполнена именно на выбранном экране. Ползунки Immersive Camera не меняют координаты, получаемые этим приложением.

Старый режим на Apple Vision остаётся доступен через `python app.py`; его инструкция приведена ниже.

Локальный Python-прототип: встроенная камера → Apple Vision через PyObjC → признаки глаз → 25-точечная калибровка → подбор Ridge-регрессии → сглаженная точка взгляда и CSV.

Это экспериментальная оценка направления взгляда, а не определение точного пикселя. Обычная камера и landmarks Vision могут давать большую ошибку, особенно по вертикали. После обучения приложение проверяет ошибку на **9 точках в отдельном проходе**, после выбора модели на других 5 точках. Собственная нейросеть не обучается и не скачивается; сам Vision использует встроенные модели Apple.

## Установка

Нужны macOS 14+ и Python 3.11–3.14 для Apple Silicon (arm64). Проверено окружение Python 3.14.4; версии установленных библиотек приведены в `requirements-tested.txt`.

Откройте Terminal в папке этого проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python app.py
```

Для воспроизведения проверенного набора зависимостей замените `requirements.txt` на `requirements-tested.txt`.

При запросе macOS разрешите доступ к камере приложению, из которого запущен Python (например, Terminal). Если доступ был запрещён: System Settings → Privacy & Security → Camera, разрешите его и перезапустите Terminal. Доступ к записи экрана или Accessibility не требуется.

## Калибровка и работа

1. Сделайте встроенный экран **основным** в настройках macOS. MVP работает только с основным дисплеем, в собственном полноэкранном окне.
2. Поставьте ноутбук неподвижно, сядьте примерно в 50–70 см. Обеспечьте ровный свет без сильных бликов на очках. В системных видеоэффектах отключите Center Stage и Portrait, если они доступны. Не меняйте положение экрана, освещение, масштаб дисплея или расстояние до камеры после калибровки.
3. Посмотрите в центр жёлтой точки и нажмите **Space**. Продолжайте смотреть на неё: приложение ждёт 1 секунду, затем собирает 35 валидных кадров. Обычно это несколько секунд. Для следующей точки снова нажмите Space — автоматического переключения в сбор нет.
4. Пройдите 25 точек обучения (сетка до 5% от краёв), затем 5 точек подбора модели и 9 точек итоговой проверки. Всего 39 остановок. На каждом этапе нажимайте Space для начала сбора. Итоговые 9 точек не используются ни для обучения, ни для выбора модели; центр повторяет обучающую позицию, но кадры собираются заново.
5. Появится зелёная точка и начнётся запись CSV. Вверху — медианная ошибка и 90-й перцентиль ошибки проверки в физических пикселях. Это ошибка отдельных **несглаженных и необрезанных** предсказаний относительно целей; цифры зависят и от того, насколько точно вы смотрели на цель.

**D** — показать/скрыть изображение глаз: зелёные точки обозначают контуры, красные — зрачки Vision. Отключайте просмотр перед калибровкой, чтобы он не отвлекал и не закрывал мишени. Поворачивайте взгляд при неподвижной голове и проверяйте, остаются ли красные отметки на зрачках.

После проверки под общей ошибкой выводятся 3 строки по 3 значения: верх экрана, середина, низ; в каждой строке слева направо. Это медианные ошибки отдельных мишеней, а не оценка всей площади региона.

**C** — новая калибровка. **Esc / Q** — завершить, закрыть файл, освободить камеру.

При потере лица/зрачков точка скрывается, CSV приостанавливается, фильтр сбрасывается. Старые координаты не записываются как новые. Если 20 секунд не хватает для сбора точки, нажмите Space ещё раз после исправления освещения. Должно быть видно ровно одно лицо.

При изменении размеров основного дисплея приложение останавливает оценку: закройте его и запустите заново. При любом переключении основного экрана также перезапускайте приложение.

## Параметры

```bash
python app.py --camera 0 --samples 35 --smoothing 0.15
python app.py --camera 1 --output sessions/my-experiment
```

- `--camera`: индекс камеры AVFoundation. Если индекс 0 выбирает внешнюю/Continuity-камеру, попробуйте другой индекс; автоматического выбора встроенной камеры нет.
- `--samples`: число валидных кадров на точку, минимум 10.
- `--smoothing`: постоянная времени EMA в секундах, 0.01–2. Больше — плавнее, но выше задержка.
- `--output`: папка сессии; по умолчанию создаётся уникальная папка `sessions/<дата-время>`. Существующий `trajectory.csv` не перезаписывается.

## Результаты и координаты

В папке сессии:

- `trajectory.csv` — только валидные кадры после обучения и проверки, `timestamp,x,y`.
- `session.json` — размеры экрана, параметры, система координат и результат каждой завершённой проверки, ошибки по 9 мишеням и сравнение 10 вариантов модели.
- `calibration-N.npz` — признаки, цели и коэффициенты модели каждой калибровки. Автоматической загрузки нет: при новом запуске калибруйтесь заново.

```csv
timestamp,x,y
1789549200.123456,1511.40,981.25
```

`timestamp` — Unix-время в секундах UTC, снятое сразу после чтения кадра, до обработки Vision. Это время на компьютере, не аппаратный timestamp экспозиции. Координаты `x,y` — сглаженная оценка, ограниченная границами **основного дисплея**: начало сверху слева, X вправо, Y вниз. Диапазон `[0, width−1] × [0, height−1]`, значения могут быть дробными.

Размер физической пиксельной сетки берётся из `CGDisplayPixelsWide/High`. Это не логические points Qt и не глобальные координаты рабочего стола с несколькими мониторами. На Retina UI работает в логических координатах, а нормализованная оценка отдельно переводится в пиксели. `session.json` фиксирует оба размера. При нестандартном scaled-режиме это сетка дисплея, сообщаемая Core Graphics, а не обязательно размер рендер-буфера скриншота.

Кадры камеры не сохраняются и не отправляются в сеть. `.npz` содержит числовые признаки лица, CSV — траекторию взгляда. Файлы записываются локально. После установки сетевое соединение не требуется.

## Как устроено

- OpenCV/AVFoundation получает кадр без программного зеркального отражения с запросом 1280×720. Фактический режим выбирает драйвер камеры.
- PyObjC сначала вызывает `VNDetectFaceRectanglesRequest` revision 3 для обнаружения лица, затем передаёт найденное лицо в `VNDetectFaceLandmarksRequest` revision 3. Углы головы для регрессии не запрашиваются. Для простоты кадр передаётся как JPEG в памяти; это добавляет небольшую задержку. У приложения есть ограничитель примерно 20 итераций/с; фактическая скорость зависит от камеры и Vision.
- Извлекаются 6 признаков: для каждого глаза положение зрачка относительно центра bounding box глаза, нормированное на ширину, и отношение высоты глаза к ширине. Ширина используется только для нормализации; отдельным признаком не является. Углы головы и положение/размер лица в регрессию не входят. Схема `eyes_only_v1` и имена признаков сохраняются в JSON/NPZ.
- Отбрасываются отсутствующие landmarks, низкая уверенность лица и очень узкие глаза (эвристика моргания; это не надёжный детектор моргания).
- Сравниваются линейная Ridge-регрессия и вариант с квадратами/попарными произведениями четырёх координат зрачков (всего 16 признаков). Признаки стандартизуются только по обучающим данным. Для каждой модели проверяются `alpha=0.1,1,10,30,100`; выбирается минимальная средняя ошибка на 5 отдельных точках подбора. Все точки имеют одинаковое число кадров. Итоговая проверка не меняет модель. Собственной нейросети и scikit-learn нет.
- Камера/Vision работают в отдельном потоке. UI читает только последний обработанный кадр, не накапливая очередь. Кадры старше 0.5 с не используются. EMA учитывает интервал между кадрами.

Компенсации положения головы нет: сохраняйте посадку во время калибровки и использования. Зрачки Vision — оценённые landmarks, не инфракрасный eye tracker. Если ошибка велика, сначала улучшите свет и повторите калибровку; малую ошибку на обучающих данных нельзя считать доказательством точности. Окно не является оверлеем поверх других приложений, указатель мыши не перемещается.

## Проверка без камеры

Если при запуске нет окна или оно пустое, остановите процесс (Ctrl+C в Terminal; при зависании используйте принудительное завершение) и запустите:

```bash
python -u app.py --windowed --ui-only --diagnose
```

Должны появиться жёлтая точка и подписи в обычном окне. Камера в этом режиме не открывается, Space не начинает сбор. Затем проверьте камеру:

```bash
python -u app.py --windowed --diagnose
```

Логи показывают загрузку библиотек, запуск Qt, открытие камеры, первый кадр и первый ответ Vision. `--diagnose` каждые 15 секунд печатает стеки потоков для диагностики зависаний; эти сообщения сами по себе не означают ошибку. Для обычной калибровки используйте `python app.py` без диагностических флагов: оконный режим предназначен только для поиска проблем.

```bash
python -m unittest discover -s tests -v
python app.py --help
```

Тесты проверяют восстановление линейной зависимости на новых данных, константные признаки, фильтр при разной частоте кадров/потере лица, границы координат и нормализацию глаза. Интеграционный тест без камеры проходит 25+5+9 точек, запись CSV, отбрасывание старых кадров, отрисовку окна и повторную калибровку.

Проверено после перехода на признаки глаз: 9 тестов, включая работу при отсутствующих углах головы. При первоначальной сборке проверены импорт зависимостей, запуск `--help` и реальный вызов Apple Vision на пустом изображении (корректно вернул отсутствие лица). В ограниченном окружении Codex Vision возвращал системную ошибку Code=9; тот же вызов вне ограничений прошёл. Камера и извлечение landmarks с реального лица здесь не проверялись. Реальную точность и сквозную работу с вашим лицом нужно проверить вручную по процедуре выше.

Если камера недоступна, закройте другие приложения с камерой, проверьте разрешение и индекс. Если Vision не видит зрачки — смотрите прямо, приблизьтесь немного и исключите блики. Сообщение об ошибке выводится в нижней части окна. На первом запуске загрузка системных компонентов может занять больше времени.

Документация API: [PyObjC Vision](https://pyobjc.readthedocs.io/en/latest/apinotes/Vision.html), [VNFaceObservation](https://developer.apple.com/documentation/vision/vnfaceobservation), [VNFaceLandmarkRegion2D](https://developer.apple.com/documentation/vision/vnfacelandmarkregion2d).

## Обновление точности

Улучшение на реальном лице пока не измерено. Нелинейный вариант выбирается только при меньшей ошибке подбора; большее число точек не гарантирует точность. Сравните итоговые ошибки нескольких сессий при одинаковой посадке и свете. Старые коэффициенты автоматически не загружаются. Зависимости не изменились.

После обновления на `eyes_only_v1` пройдите калибровку заново. Старые NPZ с 15 признаками относятся к предыдущей схеме; программа их автоматически не загружает.
